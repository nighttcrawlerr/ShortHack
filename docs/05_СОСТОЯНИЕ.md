## 1. Что это

**SaluteAgent** — ИИ-помощник технической поддержки. Принимает обращение,
разбирает его языковой моделью, находит ответ в базе знаний, **проверяет
собственный ответ на выдумки** и отправляет. Человек подключается только там,
где проверка нашла замечание.

Кейс ShortHack от СберТеха: помощник, который анализирует обращения через API
языковой модели и организует дальнейшую работу с ними.

## 4. Модель и поиск

| Параметр | Значение | Почему так |
|---|---|---|
| Провайдер | `yandex`, протокол OpenAI | `https://llm.api.cloud.yandex.net/v1` |
| Модель | `yandexgpt-5-pro` | Замеряли: 0.9 с против 3 с у Qwen3-35B и 28 с у Qwen3-235B, при лучшем русском |
| Эмбеддинги | `text-embeddings-v2-doc` и `-query` | Раздельные модели для документа и запроса, 256 измерений |

Переключение модели — одна строка `LLM_MODEL` в `.env`. В том же каталоге

**Ограничение частоты.** Эмбеддинги отдаются по одному тексту за запрос

с нарастающей паузой. Индекс из 39 фрагментов строится за 9 секунд.

## 5. Как работает прогон

```
        обращение (чат, письмо или расшифровка звонка)
                        │
 1  модель   Аналитик          свободный текст → структура
 2  код      Поисковик         похожие закрытые заявки и их решения
 3  код      Поисковик         гибридный поиск по базе знаний
 4  модель   Маршрутизатор     выбор инструмента через tool calling
 5  модель   Автор ответа      ответ строго по фрагментам, со ссылками
 6  код+мод. Проверяющий       проверка на искажения
                        │          не прошло → переписать один раз
                        │          снова не прошло → остановить
 7  код      Исполнитель       заявка / уточнение / черновик ответа
                        │
            ┌───────────┴────────────┐
   проверка пройдена          есть замечание
            │                        │
   уходит пользователю        ждёт человека на /admin
```

Модель работает на четырёх шагах из семи. Среднее время разбора 4.5 секунды.

## 6. Проверка на искажения, главная часть проекта

**Первый слой — код, миллисекунды, без модели.** `backend/app/agent/verifier.py`

| Проверка | Зачем |
|---|---|
| Ссылки `[1]` разрешаются в реальные фрагменты | Модель любит сослаться на несуществующий источник |
| Каждое утверждение имеет ссылку | Утверждение без опоры — кандидат в выдумки |
| Числа, коды ошибок, телефоны, адреса, сетевые пути | Классическая галлюцинация: выдуманный номер поддержки |
| Обещания сроков, гарантий, оплаты | Помощник не имеет права обещать от лица компании |
| Доля слов ответа, встречающихся в источниках | Ловит вольный пересказ вместо инструкции |

**Второй слой — отдельный вызов модели** с противоположной установкой: разобрать
ответ на утверждения и по каждому дать вердикт. Отдельно ищет три отказа RAG:
склейку шагов из разных инструкций, распространение частного случая на общий,
подмену значений из источника.

**Два режима.** Ответ проверяется по правилам для утверждений. Уточняющее
письмо — только на выдуманные факты и обещания: вопрос ничего не утверждает,
требовать к нему ссылку бессмысленно. Режим задаётся параметром `mode`.

**Порог.** Выше 0.85 и без критических нарушений — отправляется само.
Иначе уходит человеку. Управляется переменной `AUTO_SEND`.

## 7. Поиск

`backend/app/rag/`

- `chunker.py` режет статьи по смысловым блокам, инструкция не рвётся пополам
- `tokens.py` грубая лемматизация русских окончаний плюс словарь разговорных
  написаний: «впн» находит VPN
- `bm25.py` лексический слой, настоящий BM25 в чистом Python
- `embeddings.py` векторный слой, три взаимозаменяемых источника, включая «нет»
- `retriever.py` слияние двух списков по взаимному рангу

**Запрос к поиску строится из разбора, а не из письма целиком.** В письме
половина текста — приветствие и жалобы, для поиска это шум.

Вес заголовка статьи и ключевых слов удвоен: совпадение по теме статьи должно
значить больше случайного совпадения по слову из середины текста.

Без эмбеддингов поиск продолжает работать, просто хуже на перефразировках.
Состояние видно в шапке интерфейса.

## 8. Обучение на правках оператора

`backend/app/learning.py`

Дообучить модель на диалогах операторов Сбера с клиентами **нельзя**: они
закрыты и содержат персональные данные. Сочинять их и выдавать за обучающую
выборку мы не стали.

Система учится на собственных данных. Каждая правка оператора — приоритета,
категории, команды, текста письма — сохраняется вместе с выжимкой обращения:
видно, что предложил агент и на что исправил человек. Отклонение предложения
тоже записывается.

Дальше правки работают двумя путями.

**Сразу.** Подмешиваются в промпт разбора как примеры, переписанные письма —
в промпт автора ответа как образец тона. Работает с первой правки.

**Позже.** `GET /api/training/dataset.jsonl` отдаёт накопленное в формате
Yandex Cloud. `GET /api/training/corrections` показывает, что система уже
узнала. Порог для настоящего дообучения условно поставлен в 500 правок.

Проверено на одном случае: правка приоритета Wi-Fi записалась и попала
в промпт дословно. **Эффект на объёме не проверялся**, по одному примеру
нельзя утверждать, что сработал именно он.

## 10. Грабли, на которые уже наступили

Каждая стоила времени. Не наступать снова.

**`yc` подставляет переменные окружения в файл метаданных.** `$GIT_REPO`
становится пустой строкой, `$HOME` разворачивается в локальный путь
разработчика, экранирование обратным слэшем не спасает. Из-за этого на машину
уезжал скрипт с `git clone ""` и nginx без `$host`. Лечится кодировкой base64:
подставлять в ней нечего. Сделано в `deploy/make_userdata.py`.

**Правило `pages/` в `.gitignore`** совпадало не только с отрендеренными
страницами кейса, но и с `frontend/src/pages`. Три страницы интерфейса
не попали в репозиторий, чистый клон не собирался. Нашлось только повторным
клонированием. Правила теперь привязаны к корню: `/pages/`.

**Многоточие сразу после переменной в bash.** `echo "$ZONE…"` — bash включает
байты многоточия в имя переменной и при `set -u` падает.

**Перелив рамки рвался.** При `background-repeat` повторяется плитка фона,
её размер по умолчанию равен блоку, а не периоду градиента. Лечится
`background-size: 240px 100%` плюс совпадающие первый и последний цвет.

**Правка после автоотправки терялась.** `/apply` искал только заявки
со статусом `proposed`, а при автоотправке заявка уже в работе. Это самый
частый случай правки, и он не записывался.

**Порог уверенности ломал работу без ключа.** У заглушки уверенность —
константа 0.5, и порог 0.6 отправлял человеку вообще всё. Тот, кто клонировал
репозиторий и запускал без ключа, видел неработающий продукт.

**Ключ «вход» в заглушке ловил слово «входящего»** из шапки каждой расшифровки
звонка, и все звонки уезжали в категорию доступов.

**Ошибка построения индекса проглатывалась молча**, и поиск тихо
деградировал до лексического. Теперь возвращается наружу.
